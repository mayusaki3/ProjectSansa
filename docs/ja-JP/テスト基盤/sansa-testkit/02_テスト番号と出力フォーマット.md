# テスト番号と出力フォーマット

## テスト番号の規約

テスト番号は、以下の形式で付与します。

- `MXX:UT-aa-bbb`
- `MXX:IT-aa-bbb`

ここで:

- `MXX` : モジュールID（例: `M01` = sansa-auth / 認証・セッション）
- `UT` / `IT` : 単体テスト（Unit Test） / 結合テスト（Integration Test）
- `aa` : テストグループ番号（機能・シナリオ単位）
- `bbb` : 個々のテストケース番号

例:

- `M01:UT-01-001` : sansa-auth / 単体テスト / グループ01 / ケース001
- `M01:IT-02-003` : sansa-auth / 結合テスト / グループ02 / ケース003

このテスト番号は、以下のものと 1:1 で対応することを目標とします。

- テストマトリクス（例: `M01_認証セッション_テストマトリクス.md`）
- 実際のテストコード（クラス名・メソッド名）
- テスト実行ログ（`TestPrinter` による標準出力）

## TestPrinter による出力フォーマット（例）

`sansa-testkit` の `TestPrinter` は、テスト番号と結果を整形して出力します。  
出力の例（イメージ）は以下のとおりです。

- ケース単位の出力例:

  - 成功: `✅[M01:UT-01-001] 正常系: 事前登録メール送信`
  - 失敗: `❌[M01:UT-01-002] 異常系: メールアドレス形式不正`

- グループサマリの出力例:

  - `--- SUMMARY M01:UT-01: ✅=3 / ❌=1 / TOTAL=4 ---`

将来的に、ダミー実装に対するテストであることを明示するため、例えば以下のような拡張を検討します。

- ダミー実装テスト: `✅[M01:UT-01-001][DUMMY] 正常系: 事前登録メール送信（ダミー実装）`

この場合の `[DUMMY]` 部分は、`@DummyImplementation` 等のマーカーアノテーションを起点に `TestPrinter` 側で自動付与することを想定しています。

## JUnit との関係

- JUnit 5（Jupiter）ベースのテストに対して `TestPrinter` を呼び出して利用します。
- テストの成否自体は JUnit が判定し、`TestPrinter` は「人間がログを読みやすくするためのフォーマッタ」として振る舞います。
