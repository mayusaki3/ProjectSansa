# テスト番号と出力フォーマット

## テスト番号の規約

テスト番号は、以下の形式で付与します。

- `MXX:UT-aa-bbb`
- `MXX:IT-aa-bbb`

ここで:

- `MXX` : モジュールID（例: `M01` = sansa-auth / 認証・セッション）
- `UT` / `IT` : 単体テスト（Unit Test） / 結合テスト（Integration Test）
- `aa` : テストグループ番号（機能・シナリオ単位）
- `bbb` : 個々のテストケース番号

例:

- `M01:UT-01-001` : sansa-auth / 単体テスト / グループ01 / ケース001
- `M01:IT-02-003` : sansa-auth / 結合テスト / グループ02 / ケース003

このテスト番号は、以下のものと 1:1 で対応することを目標とします。

- テストマトリクス（例: `M01_認証セッション_テストマトリクス.md`）
- 実際のテストコード（クラス名・メソッド名）
- テスト実行ログ（`TestPrinter` による標準出力）

## TestPrinter による出力フォーマット（例）

`sansa-testkit` の `TestPrinter` は、テスト番号と結果を整形して出力します。  
出力の例（イメージ）は以下のとおりです。

- ケース単位の出力例:

  - 成功: `✅[M01:UT-01-001] 正常系: 事前登録メール送信`
  - 失敗: `❌[M01:UT-01-002] 異常系: メールアドレス形式不正`

- グループサマリの出力例:

  - `--- SUMMARY M01:UT-01: ✅=3 / ❌=1 / TOTAL=4 ---`

## ダミー実装に対する出力（[DUMMY]）

sansa-testkit では、テスト対象クラスに `@DummyImplementation` が付与されている場合、  
そのテスト結果行のテスト番号の後に `[DUMMY]` を付与して出力します。

- 目的:
  - 「テストは成功しているが、実装はダミーである」状態を明示する
  - 初期フェーズでの一時的な実装と、本番実装を視覚的に区別する
- 対象:
  - テスト対象クラス（Service 実装や Repository など）に `@DummyImplementation` が付与されている場合

### 出力例

以下は、通常のテストとダミー実装に対するテストが混在している例です。

```text
=== M01:UT-01-001 User Registration Flow ===
✅ [M01:UT-01-001] preRegister: 正常系（メール送信成功）
✅ [M01:UT-01-002] verifyEmail: 正常系（コード一致）
✅ [M01:UT-01-003] [DUMMY] register: ダミー実装（パスワード検証ロジック未実装）

--- SUMMARY M01:UT-01: ✅=3 / ❌=0 / TOTAL=3 ---
```

- 上記のように、`[DUMMY]` が付与されている行は **ダミー実装に対するテスト** であることを表します。
- `[DUMMY]` が付与されていないものは、本実装（または少なくともダミーと明示されていない実装）を対象としたテストです。

## JUnit との関係

- JUnit 5（Jupiter）ベースのテストに対して `TestPrinter` を呼び出して利用します。
- テストの成否自体は JUnit が判定し、`TestPrinter` は「人間がログを読みやすくするためのフォーマッタ」として振る舞います。
