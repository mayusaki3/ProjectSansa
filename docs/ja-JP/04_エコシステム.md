# エコシステム

## 1. 概要

ProjectSansa は、Sansaエコシステム全体の設計思想・共通概念・リポジトリ間連携を管理する中核リポジトリです。

Sansaエコシステムは、1つの巨大な monorepo ではなく、役割ごとにリポジトリを分離して連携する
「リポジトリ連携構成（repository federation）」
を採用します。

例えば、以下はそれぞれ専用リポジトリとして分離します。

- XR runtime
- VRM format
- AI workflow
- rendering
- networking
- governance

ProjectSansa 自体は、ゲーム engine や runtime の実装リポジトリではなく、全体設計と共通方針を管理する役割を持ちます。

---

## 2. なぜリポジトリを分離するのか

Sansaエコシステムは、XR / AI / VRM / rendering / networking / governance など、多数の技術領域から構成されます。

これらを単一リポジトリへ集約すると、以下の問題が発生します。

- リポジトリが巨大化する
- 依存関係が複雑化する
- 無関係な実装が混在する
- リポジトリごとの責務が不明瞭になる
- LLM がリポジトリの責務を誤認しやすくなる
- リポジトリごとの独立進化が難しくなる

そのため、役割ごとにリポジトリを分離し、ProjectSansa がそれらを連携・統合する構成を採用します。

---

## 3. ProjectSansa の役割

ProjectSansa は、Sansaエコシステム全体の共通管理リポジトリとして扱います。

主に以下を管理します。

- 全体設計（ecosystem architecture）
- リポジトリ連携構成（repository federation）
- 共通用語（shared terminology）
- ガバナンス方針（governance policy）
- provenance 方針
- リポジトリ間調整
- LLM 申し送り管理

ProjectSansa 自体は、runtime implementation を主責務としません。

---

## 4. エコシステム共通方針

### local-first

ローカル環境のみでも主要 workflow を成立可能とします。

### offline-first

ネットワーク接続なしでも主要 workflow を継続可能とします。

### creator-first

creator ownership / creator workflow / creator control を重視します。

### optional ecosystem integration

ecosystem integration は optional とし、常時オンライン接続を前提にしません。

---

## 6. リポジトリごとの役割

### ProjectSansa

Sansaエコシステム 全体の設計・共通方針を扱います。

### SansaXR

XR runtime / networking / OpenXR を扱います。

### SansaVRM

VRM format / validator / schema を扱います。

### SansaVRM-MuJoCo-Adapter

MuJoCo 連携を扱います。

### SansaVRM-Studio-AI

AI-assisted workflow を扱います。

### SansaCloth

cloth interaction / anti-clipping / rendering を扱います。

---

## 7. 依存関係方針

リポジトリ間 dependency は、一方向 dependency を基本とします。

```text
SansaXR → SansaVRM
```

これは、

- runtime が format を利用する

方向です。

逆方向である：

```text
SansaVRM → SansaXR
```

は原則として避けます。

format layer が runtime implementation に依存しない構成を維持します。

---

## 8. 実装分離方針

ProjectSansa では、以下を原則として保持しません。

- engine-specific implementation
- runtime implementation
- rendering implementation
- game-specific implementation

例えば：

```text
src/GameEngine/
```

のような実装は、専用リポジトリ側へ分離します。

---

## 9. 共通用語管理

ProjectSansa は、Sansaエコシステム 全体の共通用語管理元として扱います。

各リポジトリは、

- 共通用語を参照する
- リポジトリ固有拡張のみ追加する

構成を基本とします。

これにより、リポジトリ間の意味的不整合（semantic divergence）を防ぎます。

---

## 10. 目的

リポジトリ連携構成により、以下を実現します。

- implementation monorepo 化回避
- リポジトリ責務分離
- リポジトリごとの独立進化
- dependency explosion 抑制
- ecosystem-wide interoperability 維持
- LLM による repository 誤認識防止
