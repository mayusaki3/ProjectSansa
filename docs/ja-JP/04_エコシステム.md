# エコシステム

## 1. 概要

ProjectSansa ecosystem は、repository federation 構成を採用します。

ProjectSansa 自体は ecosystem / federation / architecture を主責務とし、implementation monorepo 化を避けます。

runtime / format / AI / rendering などの implementation は、専用 repository へ分離します。

---

## 2. ProjectSansa の役割

ProjectSansa は、Sansa ecosystem 全体における ecosystem-wide shared concepts / governance / federation を扱います。

ProjectSansa 自体は implementation repository ではなく、以下を主責務とします。

- ecosystem architecture
- repository federation
- shared terminology
- shared governance model
- shared provenance model
- ecosystem-wide policy
- federation policy
- repository coordination
- handover coordination

---

## 3. ecosystem-wide policy

### local-first

ローカル環境のみで主要 workflow を成立可能とします。

### offline-first

ネットワーク接続なしでも主要 workflow を継続可能とします。

### creator-first

creator ownership / creator workflow / creator control を重視します。

### optional ecosystem integration

ecosystem integration は optional とし、mandatory online runtime を前提にしません。

---

## 4. repository federation

ProjectSansa ecosystem は、repository federation により構成されます。

```text
ProjectSansa
├─ ecosystem architecture
├─ federation
├─ repository map
├─ interoperability
├─ compatibility
└─ roadmap

SansaXR
├─ XR runtime
├─ OpenXR
├─ networking
├─ multiplayer
└─ runtime implementation

SansaVRM
├─ avatar format
├─ validator
├─ canonicalization
└─ adapters

SansaVRM-MuJoCo-Adapter
├─ MuJoCo adapter
├─ MJCF integration
├─ diagnostics
└─ schema validation

SansaVRM-Studio-AI
├─ AI tooling
├─ image→3D
└─ local AI integration

SansaCloth
├─ anti-clipping
├─ cloth interaction
├─ shader abstraction
└─ rendering integration
```

---

## 5. repository role examples

### ProjectSansa

ecosystem / federation / architecture の canonical repository。

### SansaXR

XR runtime / networking / OpenXR の canonical repository。

### SansaVRM

avatar format / validator / canonicalization の canonical repository。

### SansaVRM-MuJoCo-Adapter

MuJoCo integration の canonical repository。

### SansaVRM-Studio-AI

AI-assisted avatar tooling の canonical repository。

### SansaCloth

cloth interaction / anti-clipping / rendering integration の canonical repository。

---

## 6. dependency direction

```text
ProjectSansa
 ├─ SansaXR
 │   └─ depends on SansaVRM
 │
 ├─ SansaVRM
 │
 ├─ SansaVRM-MuJoCo-Adapter
 │   └─ depends on SansaVRM
 │
 ├─ SansaVRM-Studio-AI
 │   └─ depends on SansaVRM
 │
 └─ SansaCloth
     └─ depends on SansaVRM
```

以下は原則として避けます。

```text
SansaVRM → SansaXR
```

フォーマット層が runtime implementation に依存しない構成を維持します。

---

## 7. implementation 分離方針

ProjectSansa では、以下を原則として保持しません。

- engine-specific implementation
- runtime implementation
- rendering implementation
- single repository specific implementation

以下のような engine / runtime 実装は分離対象とします。

```text
src/GameEngine/
```

実装成果物は、必要に応じて SansaXR などの専用 repository へ移行します。

---

## 8. shared terminology

ProjectSansa は ecosystem-wide shared terminology authority として扱います。

各 repository は terminology consumer として扱い、repository-specific extension のみ定義します。

---

## 9. 目的

repository federation 構成により、以下を実現します。

- implementation monorepo 化回避
- repository 責務分離
- independent evolution
- dependency explosion 抑制
- runtime / format / AI / rendering の独立進化
- ecosystem-level interoperability 維持
