# Cassandra スキーマ反映手順（sansa-auth）

> 本ドキュメントは「データ定義 目次」にぶら下がる運用手順です。

## 前提
- Cassandra 4.x（単一/3ノードいずれも可）
- `cqlsh` が利用可能
- リポジトリ内配置: `cassandra/cql/sansa_auth/V0001__init.cql`

> 既定キー スペース：`sansa_auth`（RF=1／開発想定）。本番は RF を 3 以上に変更してください。

---

## 1) 起動（ローカル Docker 例）
```bash
docker run -d --name cassandra -p 9042:9042 cassandra:4
# 初回起動安定まで待機
docker logs -f cassandra
```

## 2) スキーマ適用
```bash
HOST=127.0.0.1
PORT=9042
USER=cassandra
PASS=cassandra

cqlsh $HOST $PORT -u $USER -p $PASS -f cassandra/cql/sansa_auth/V0001__init.cql
```

## （本番／多ノード）RF の見直し例
```sql
コードをコピーする
CREATE KEYSPACE IF NOT EXISTS sansa_auth
  WITH replication = {'class': 'NetworkTopologyStrategy', 'dc1': 3}
  AND durable_writes = true;
```

## 3) 検証
```bash
# キースペース
cqlsh -e "DESCRIBE KEYSPACE sansa_auth"

# 代表テーブル
cqlsh -e "DESCRIBE TABLE sansa_auth.users"
cqlsh -e "DESCRIBE TABLE sansa_auth.sessions"
cqlsh -e "DESCRIBE TABLE sansa_auth.auth_audit_log"

# TTL 例：メール認証
cqlsh -e "DESCRIBE TABLE sansa_auth.email_verifications"
```

## 4) Spring Boot 側の接続
application-cassandra.yml を有効化して起動/テスト。

## 起動（ローカル）
```bash
set SPRING_PROFILES_ACTIVE=cassandra
./mvnw spring-boot:run
```

## テスト（プロファイル指定）
```bash
./mvnw -Dspring.profiles.active=cassandra verify
Cassandra 確認時は 必ず cassandra プロファイルを使用。
```

## 5) 典型トラブルと対処
- NoHostAvailableException: 起動未完/ポート/認証を再確認。
- AlreadyExists（再適用時）: 既存なら無視可。やり直しは DROP KEYSPACE sansa_auth; → 再適用。
- RF が 1 のまま: 本番前に ALTER KEYSPACE で RF を適切化し、nodetool status で確認。

## 6) ロールバック方針（開発/検証）
```sql
DROP KEYSPACE IF EXISTS sansa_auth;
```
→ その後 V0001__init.cql を再適用。

## 7) 運用メモ
- スキーマ変更は 新しい CQL を追加（例：V0002__add_indexes.cql）し履歴管理。
- 適用順はファイル名の連番で制御。
- 本番適用はメンテ時間帯に実施し、適用後に RF/リング健全性を nodetool で確認。

```makefile
::contentReference[oaicite:0]{index=0}
```
