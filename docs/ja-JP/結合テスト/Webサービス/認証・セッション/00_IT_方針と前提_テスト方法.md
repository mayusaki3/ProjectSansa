# 結合テスト方針と前提 / テスト方法

## 目的
- 01〜09 の結合観点で、認証・WebAuthn・MFA・セッション・トークン・監査・レート制限・i18n を横断的に検証する。
- 単体テストの網羅を前提に、**コンポーネント間の接続点（Controller⇄Service⇄Repo、外部メール/時刻/鍵束）**を重点確認。

## 前提/共通
- ベースURL: `${BASE_URL}`
- 認証ヘッダ: `Authorization: Bearer <accessToken>`
- 言語: 入力 `Accept-Language` / 出力 `Content-Language`
- エラーフォーマット: `application/problem+json`
- テストデータ:
  - 許可ドメイン: `example.com`
  - ブロックドメイン: `blocked.test`（ disposable/deny リスト）
  - 既存ユーザー: なし（テスト内で作成/破棄）

## 命名規約
- テストID: `IT-<章番号>-<通し3桁>`（例: `IT-01-001`）
- 章番号:
  - 01: 登録フロー（pre-register / verify-email / register）
  - 02: WebAuthn（登録・認証・管理）
  - 03: ログイン（パスワード / WebAuthn / MFA誘導）
  - 04: セッション（現在/列挙/個別失効）
  - 05: ログアウト（単体 / 全端末=logout_all）
  - 06: トークン（TTL/リフレッシュ/改竄/tv）
  - 07: MFA（TOTP / Email OTP / Recovery）
  - 08: 監査・レート制限
  - 09: i18n / problem+json / セキュリティヘッダ

## 記述形式
- 各ケースは **Given / When / Then** で記述し、**期待ステータス・主要レスポンスキー**を明示。

## Cassandra 用 IT の起動方法（CassandraITBootstrap を使用）

### 前提
- Docker Desktop（Windows/Mac）または Docker Engine（Linux）
- `docker compose` が利用可能であること（Compose v2）
- Windows の場合は **WSL2** を有効化

### 役割
- `src/testCassandra/java/com/sansa/auth/it/CassandraITBootstrap.java` が **Testcontainers** で Cassandra を起動し、  
  キースペース `sansa_auth` を作成し、`cassandra/cql/sansa_auth` 配下の **最新 `V*__init.cql`** を適用します。
- Spring プロファイルは `cassandra` を使用します（`application-cassandra.yml`）。

### 事前準備
- Docker が起動していること（`docker info` が成功する状態）。
- Maven プロファイル `it-cassandra` を有効化（POM で `src/testCassandra` を **test ソース**に追加し、Testcontainers 依存を test スコープで読み込み）。


### 起動
Docker Desktop（Windows/Mac）または Docker Engine を起動後に行う。
```shell
# プロジェクト直下で
docker compose -f docker-compose.dev.yml up -d cassandra
```
⚠️ version キーは Compose v2 では非推奨のため、警告が出ても無視可（将来は削除予定）。


### 実行コマンド
単一ノード Cassandra で IT 実行:
```bash
mvn -q "-Dspring.profiles.active=cassandra" -Pit-cassandra verify




### 初回スキーマ適用
```shell
# Cassandra が起動してから実行（数十秒待つか、STATUS=running を確認）
cqlsh -f cassandra/cql/sansa_auth/V0001__init.cql
```

### トラブルシュート（Windows）
- open //./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified.
→ Docker Desktop が起動していません。Docker Desktop を起動 → タスクトレイの Running を確認して再実行。
- cqlsh が見つからない
→ cassandra イメージから一時的に実行:
```shell
docker exec -it <cassandra_container_name> cqlsh -f /work/cassandra/cql/sansa_auth/V0001__init.cql
```

## テスト方法（Integration / IT）
### 1) inmem で IT（verify フェーズで UT+IT 実行）
```shell
# /sansa-auth で実行
.\setcp.ps1
mvn -q -DskipTests clean package
mvn -q "-Dspring.profiles.active=inmem" verify
```

### 2) Cassandra 単一ノード
事前: Cassandra を起動し、キー スペース/スキーマ（sansa_auth）を適用済みであること
```shell
docker compose -f docker-compose.dev.yml up -d cassandra
cqlsh -f cassandra/cql/sansa_auth/V0001__init.cql
```
```shell
mvn -q "-Dspring.profiles.active=cassandra" `
    "-Dcassandra.contactPoints=localhost:9042" `
    "-Dcassandra.localDatacenter=datacenter1" `
    "-Dcassandra.keyspace=sansa_auth" verify
```

### 3) Cassandra 3ノード（例: 3台のエンドポイントをカンマ区切り）
```shell
mvn -q -Dspring.profiles.active=cassandra \
  -Dcassandra.contactPoints=10.0.0.11:9042,10.0.0.12:9042,10.0.0.13:9042 \
  -Dcassandra.localDatacenter=dc1 \
  -Dcassandra.keyspace=sansa_auth \
  verify
```

### IT の絞り込み実行（Failsafe）
```shell
mvn -q -Dspring.profiles.active=cassandra -Dit.test=IT02_WebAuthnTest verify
mvn -q -Dspring.profiles.active=cassandra -Dit.test=IT02_WebAuthnTest#assertion_success verify
```

### 失敗テストのみ再実行（任意）
```
mvn -q -Dspring.profiles.active=cassandra -Dfailsafe.rerunFailingTestsCount=1 verify
```shell

### レポート出力場所
```shell
target/surefire-reports/（UT） と target/failsafe-reports/（IT）
```
