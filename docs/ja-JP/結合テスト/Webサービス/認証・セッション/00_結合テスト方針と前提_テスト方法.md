# 結合テスト方針と前提 / テスト方法

## 目的
- 01〜09 の結合観点で、認証・WebAuthn・MFA・セッション・トークン・監査・レート制限・i18n を横断的に検証する。
- 単体テストの網羅を前提に、**コンポーネント間の接続点（Controller⇄Service⇄Repo、外部メール/時刻/鍵束）**を重点確認。

## 前提/共通
- ベースURL: `${BASE_URL}`
- 認証ヘッダ: `Authorization: Bearer <accessToken>`
- 言語: 入力 `Accept-Language` / 出力 `Content-Language`
- エラーフォーマット: `application/problem+json`
- テストデータ:
  - 許可ドメイン: `example.com`
  - ブロックドメイン: `blocked.test`（ disposable/deny リスト）
  - 既存ユーザー: なし（テスト内で作成/破棄）

## 命名規約
- テストID: `M01:IT-<章番号>-<通し3桁>`（例: `M01:IT-01-001`）
- 章番号:
  - 01: 登録フロー（pre-register / verify-email / register）
  - 02: WebAuthn（登録・認証・管理）
  - 03: ログイン（パスワード / WebAuthn / MFA誘導）
  - 04: セッション（現在/列挙/個別失効）
  - 05: ログアウト（単体 / 全端末=logout_all）
  - 06: トークン（TTL/リフレッシュ/改竄/tv）
  - 07: MFA（TOTP / Email OTP / Recovery）
  - 08: 監査・レート制限
  - 09: i18n / problem+json / セキュリティヘッダ
  - 10: IT Cassandra 固有
  - 11: IT Mail メール処理E2E
  - 12: IT パスワードリセット

## 記述形式
- 各ケースは **Given / When / Then** で記述し、**期待ステータス・主要レスポンスキー**を明示。

## Cassandra 用 IT の起動方法（CassandraITBootstrap を使用）

### 役割
- `src/testCassandra/java/com/sansa/auth/it/CassandraITBootstrap.java` が **Testcontainers** で Cassandra を起動。  
キースペース `sansa_auth` を作成し、`cassandra/cql/sansa_auth` 配下の **最新 `V*__init.cql`** を自動適用します。
- Spring プロファイルは `cassandra` （`application-cassandra.yml`）を使用します。

### 事前準備（Docker）
- Docker Desktop（Windows/Mac）または Docker Engine（Linux）
- `docker compose` （Compose v2）が利用可能であること
- Windows の場合は **WSL2** を有効化
- Docker が起動済みであること（`docker info` が成功）

メモ: Composeファイルの version キーは v2 では非推奨。警告は無視可（将来は削除予定）。

### 単一ノードの起動例
Docker Desktop（Windows/Mac）または Docker Engine を起動後に行う。
```shell
# プロジェクト直下で実行

# 単一ノードの起動例
# サービス（cassandra）を compose で定義している場合:
docker compose -f docker-compose.dev.yml up -d cassandra

# 3ノード構成の起動例（任意）
# 3サービス（cassandra1/2/3）を compose で定義している場合:
docker compose -f docker-compose.dev.yml up -d cassandra1 cassandra2 cassandra3
```

### スキーマ適用について
- IT 実行時は自動適用（CassandraITBootstrap が V*__init.cql の最新を選択して適用）
- 手動確認したい場合（任意）:
```shell
# Cassandra が起動してから適用
cqlsh -f cassandra/cql/sansa_auth/V0001__init.cql
# or コンテナ経由
docker exec -it <cassandra_container_name> cqlsh -f /work/cassandra/cql/sansa_auth/V0001__init.cql
```

### Maven 側の前提
- POM の M01:IT-cassandra プロファイルで Testcontainers 依存 と testCassandra ソースディレクトリ を有効化していること
- 例: -PM01:IT-cassandra を付けて実行
- 例: PowerShellでは -D オプションは二重引用符で囲む

## テスト方法（Integration / IT）
### 1) inmem で IT（verify フェーズで UT+IT 実行）
```shell
# /sansa-auth で実行
.\setcp.ps1
mvn -q -f sansa-auth/pom.xml -DskipTests clean package
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem verify
```

### 2) Cassandra 単一ノード
事前: Cassandra 起動済み。IT 実行時は CassandraITBootstrap が自動で V*__init.cql 最新を適用（手動適用は任意）。
```shell
docker compose -f docker-compose.dev.yml up -d cassandra
```
```shell
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=cassandra `
    -Dcassandra.contactPoints=localhost:9042 `
    -Dcassandra.localDatacenter=datacenter1 `
    -Dcassandra.keyspace=sansa_auth `
    -PM01:IT-cassandra verify
```

### 3) Cassandra 3ノード（例: 3台のエンドポイントをカンマ区切り）
```shell
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=cassandra `
  -Dcassandra.contactPoints=10.0.0.11:9042,10.0.0.12:9042,10.0.0.13:9042 `
  -Dcassandra.localDatacenter=dc1 `
  -Dcassandra.keyspace=sansa_auth `
  -PM01:IT-cassandra verify
```

### 4) MailHog + メール検証
Cassandra-IT では実 SMTP 相当として MailHog を使用する。
```shell
docker compose -f docker-compose.dev.yml up -d mailhog
# Web UI: http://localhost:8025
# SMTP:   localhost:1025
```
- メールE2E（M01:IT-11）は、JaCoCo（Java）と pytest-cov（Python）でカバレッジを CI（ci-mail-e2e.yml）にて評価・保存する。 :contentReference[oaicite:1]{index=1}
- reset.init / reset.complete 送信メールのテンプレート検証を IT-12 で実施する。

実行と確認
1. Cassandra を起動（単一ノード or 3ノード）。
2. MailHog を起動。
3. Maven で Cassandra-IT を実行：
```shell
mvn --% -q -f sansa-auth/pom.xml "-Dspring.profiles.active=cassandra `
    -Dcassandra.contactPoints=localhost:9042 `
    -Dcassandra.localDatacenter=datacenter1 `
    -Dcassandra.keyspace=sansa_auth `
    -PM01:IT-cassandra verify
```
4. Web UI（http://localhost:8025）でメールが到達していることを確認。
- 件名・本文の言語（Accept-Language に応じたテンプレート適用）
- ワンタイムコード/URL のフォーマット

### 5) 追加推奨テスト（後続で実装）
- **M01:IT-01-008**: `verify-email` 送信 → MailHog で件名/本文/コード検証（ja-JP / en-US）  
- **M01:IT-07-007**: **Email OTP**: 送信→受信→検証（TTL 失効/再送間隔/レート制限も）  
- **M01:IT-07-008**: **Recovery codes** 発行メールの一度きり表示の保証  
- **エラーメール抑止**: ブロックドメイン/レート超過時に送らないこと

> 既存 UT/IT（inmem）では OutBox を検査、Cassandra-IT では MailHog 経由で E2E 検証、という住み分けです。

### 6) 実行例
```shell
# inmem UT/IT
mvn -q -f sansa-auth/pom.xml -DskipTests clean package
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem verify

# Cassandra-IT（単一ノード）
docker compose -f docker-compose.dev.yml up -d cassandra mailhog
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=cassandra `
    -Dcassandra.contactPoints=localhost:9042 `
    -Dcassandra.localDatacenter=datacenter1 `
    -Dcassandra.keyspace=sansa_auth `
    -PM01:IT-cassandra verify
```

### IT の絞り込み実行（Failsafe）
```shell
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=cassandra -PM01:IT-cassandra -Dit.test=IT02_WebAuthnTest verify
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=cassandra -PM01:IT-cassandra -Dit.test=IT02_WebAuthnTest#assertion_success verify
```

### 失敗テストのみ再実行（任意）
```shell
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=cassandra -PM01:IT-cassandra -Dfailsafe.rerunFailingTestsCount=1 verify
```
- メールテンプレート/パーサ（UT-09）は pytest-cov によるカバレッジ閾値を CI（ci-mail-offline.yml）で検証する。

### カバレッジ / レポート（JaCoCo）
- 本リポジトリは **既定ゴールが `verify`**。`verify` 実行で **毎回 HTML レポートとしきい値チェック**が走る。
- sansa-auth/pom.xml の defaultGoal=verify と JaCoCo（prepare-agent / prepare-agent-integration / report / check、coverage.min）を設定済み
- **ローカルの最低カバレッジ**は既定 **0%**（落とさない）。**CI は 100%** に上書きする。
  - ローカル例（0%）：  
    ```powershell
    mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem verify
    ```
  - CI 例（100%）：  
    ```bash
    mvn -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem -Dcoverage.min=1.00 verify
    # もしくは ci-strict プロファイル（GitHub Actions では自動有効）
    ```
  - -Dcoverage.min=1.00 で失敗した場合は、除外設定（DTO/Config 等）や IT の未到達分岐を確認
- レポート出力先（UT/IT 集約）：  
  `sansa-auth/target/site/jacoco/index.html`
