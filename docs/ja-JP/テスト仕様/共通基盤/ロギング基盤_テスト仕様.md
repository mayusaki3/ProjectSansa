# ロギング基盤（sansa-logging）テスト仕様

## 1. 目的

本書は Project Sansa の共通ロギング基盤（sansa-logging）が、
共通ロギング仕様（ロギングポリシー／監査ログポリシー／ログスキーマ共通定義）に準拠していることを
テストで担保するための「テスト範囲」と「維持すべきテストケース」を定義する。

対象はドメイン非依存の共通基盤であり、sansa-auth 等のサービス固有の監査イベントは対象外とする。

---

## 2. 対象範囲

- モジュール：sansa-logging
- パッケージ：com.sansa.logging.*

対象クラス例：
- com.sansa.logging.model.AuditRecord
- com.sansa.logging.AuditLogger
- com.sansa.logging.SystemLogger
- com.sansa.logging.impl.SimpleAuditLogger（暫定）
- com.sansa.logging.impl.JsonAuditLogger（正式実装に移行予定）

---

## 3. 非対象（本仕様で扱わないもの）

- ログのローテーション／保持期間／削除
  - これは OS / ログ基盤（logrotate / journald / 集約基盤）の責務とする。
- sansa-auth 等のサービス固有の eventType 決定ロジック
  - 各サービスのテスト仕様で担保する。

---

## 4. テストの実行方法

### 4.1 推奨（reactor 実行）

本モジュール（sansa-logging）は、テストで `sansa-testkit` を test scope 依存する。
そのため、単独実行時に依存解決が失敗しないよう、原則として reactor（複数モジュール）で実行する。

```powershell
mvn --% -pl sansa-testkit,sansa-logging -am -DskipTests=false clean test
```

期待：
- `[TESTCASE] TESTKIT-...` および `[TESTCASE] LOGGING-...` が出力される
- BUILD SUCCESS

### 4.2 代替（install 後に単独実行）

開発者の環境構築（後述）が完了しており、ローカルリポジトリに `sansa-testkit` が install 済みの場合、
sansa-logging を単独実行してよい。

手順：

1) testkit のテストが成功することを確認し、install する
```powershell
mvn --% -pl sansa-testkit -DskipTests=false clean test
mvn --% -pl sansa-testkit -DskipTests=false install
```

2) logging を単独実行する
```powershell
mvn --% -pl sansa-logging -DskipTests=false clean test
```

注意：
- install は「テスト成功後のみ」行う（失敗状態をローカルに配布しないため）
- CI では install 前提にせず、原則 reactor 実行とする

---

## 5. テストケース一覧（共通基盤）

### 5.1 AuditRecord（共通モデル）

- LOGGING-COMMON-TC-001 必須：eventType が null の場合は例外
- LOGGING-COMMON-TC-002 必須：result が null の場合は例外
- LOGGING-COMMON-TC-003 必須：details が null の場合 emptyMap として扱う
- LOGGING-COMMON-TC-004 必須：details は不変（外部から変更できない）

### 5.2 AuditLogger（暫定実装：SimpleAuditLogger）

- LOGGING-COMMON-TC-101 必須：write(null) は WARN 相当でスキップする
- LOGGING-COMMON-TC-102 必須：write(record) は SystemLogger 経由で 1 回出力する

### 5.3 SystemLogger（実装方針）

- LOGGING-COMMON-TC-201 推奨：error(message, ex) は Throwable を伴って出力されること
  - Slf4jSystemLogger の薄い委譲実装は単体テストの対象外とし、
    サービス側の統合テストまたはログ基盤設定の確認で担保する。
