# テストポリシー（Project Sansa / sansa-auth）

## 1. 目的
本書は sansa-auth におけるテスト実行方法、Spring Boot プロファイル運用、  
Maven ゴールの使い分け、および CI 実行方針を統一し、  
ローカル開発・CI・E2E の挙動を明確化する。

対象となるテスト種別は以下である。  
- UT（ユニットテスト）  
- IT（アプリ内完結の結合テスト）  
- E2E（外部クライアントからの疎通を含むテスト）  

---

## 2. テスト種別と Maven ゴールの使い分け

### 2.1 ローカル開発（API の手動動作確認）
目的：アプリケーションを手で起動し、ブラウザや curl で動作確認する。

- 使用ゴール: spring-boot:run  
- プロファイル: inmem  
- 停止方法: 手動（Ctrl+C）  
- 注意: spring-boot:run はテスト用途では使用しない（自動停止しないため）

#### 方針
spring-boot:run は テスト完了後に停止せずプロセスを保持するため、  
CI や自動テストで使用しない。

---

### 2.2 UT / IT（自動テスト）
目的：アプリ内完結のテストを自動化する。

- 使用ゴール  
  - mvn test（UT）  
  - mvn verify（failsafe-plugin による IT/E2E を含む場合）  
- プロファイル  
  - inmem（デフォルト）  
  - testCassandra（Cassandra を使う IT のみ）  
- 特徴  
  - @SpringBootTest によりサーバはテスト開始時に起動し、終了後は自動停止する  

#### 方針
- CI の標準テストでは spring-boot:run を使用しない  
- UT/IT は mvn test または mvn verify のみを使用する  
- これにより CI がハングする問題を防止する  

---

### 2.3 外部E2Eテスト（別クライアントからのアクセス）
目的：実際の HTTP 通信で API を検証する。

- 使用ゴール  
  - spring-boot:start（バックグラウンド起動）  
  - spring-boot:stop（テスト終了後に自動停止）  
- プロファイル  
  - inmem / testCassandra  
  - itest（外部依存が必要な場合）  

#### 方針
- E2E を mvn verify に組み込み、以下の順で自動実行する  
  1. spring-boot:start  
  2. failsafe による E2E テスト  
  3. spring-boot:stop  
- ローカル／CI の両方で安定して実行できる  

---

## 3. Spring Boot プロファイル運用方針

| プロファイル名 | 用途 |
|----------------|------|
| inmem | ローカル開発・UT・IT（外部依存なし） |
| testCassandra | Cassandra を使う IT |
| itest | 外部E2E 用の追加設定 |

#### 方針
- UT/IT は基本的に inmem を使用  
- Cassandra が必要な場合のみ testCassandra  
- E2E は itest を使うことで環境汚染を防止する  

---

## 4. CI におけるテスト実行ポリシー

### 4.1 UT / IT（CI 標準テスト）
- 実行コマンド: mvn -q -Dspring.profiles.active=inmem test  
  または failsafe を含む場合 mvn -q verify  
- spring-boot:run は使用しない（停止しないため CI をハングさせる）

### 4.2 Cassandra IT（必要なときのみ）
- プロファイル: testCassandra  
- 実行例  
  - mvn -q -Dspring.profiles.active=testCassandra verify  

### 4.3 外部E2E
- 実行例  
  - mvn -q -Dspring.profiles.active=itest spring-boot:start verify spring-boot:stop  

### 4.4 方針まとめ
- CI で bootRun を使うことは一切ない  
- bootRun はローカル開発専用  
- UT/IT/E2E は verify のライフサイクルに統合する  

---

## 5. 開発者向け実行フローチャート

以下を基準にコマンドを選択する。

- API を手動で確認したい  
  → spring-boot:run（プロファイル inmem、Ctrl+C で停止）

- UT/IT をまとめて回したい  
  → mvn test または mvn verify  
    （プロファイル inmem。Cassandra が必要なら testCassandra）

- 外部クライアントからの E2E を回したい  
  → mvn -q -Dspring.profiles.active=itest spring-boot:start verify spring-boot:stop  

開発者はこのフローチャートに従うことで、  
テスト用途で spring-boot:run を誤用せず、CI と同等の実行パターンを再現できる。

---

## 6. まとめ

- spring-boot:run は ローカル開発での手動動作確認専用 とし、UT/IT/E2E では使わない  
- UT/IT/E2E は すべて mvn test / mvn verify のライフサイクルに統合 する  
- E2E が必要な場合は spring-boot:start / spring-boot:stop を組み合わせて自動起動・停止させる  
- Spring Boot プロファイルは inmem / testCassandra / itest の役割を明確に分離し、  
  ローカル開発と CI で同じ方針を適用する  

このポリシーにより、ローカルと CI の挙動差異を最小化し、  
テスト実行の再現性と安定性を確保する。
