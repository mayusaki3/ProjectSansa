# 単体テスト方針 / 命名規約 / テスト方法

## 目的
- 01〜05 の API 仕様（認証・WebAuthn・MFA・セッション）を **単体で網羅**。
- DTO 検証・エラーモデル（problem+json）・レート制限・i18n ヘッダまで確認。
- （補助）メールテンプレート／差し込み／署名／TTL／i18n 検証は Python で構造化比較（UT-09）

## 命名規約
- テストID: `UT-<章番号>-<通し3桁>`（例: `UT-01-001`）
- 章番号:
  - 01: Controller 入力検証・エラー整形
  - 02: Service 登録フロー（pre-register / verify-email / register）
  - 03: Service ログイン・WebAuthn・セッション列挙/取得/失効
  - 04: Service ログアウト・全端末無効化（token_version）
  - 05: Util トークン署名・TTL・検証
  - 06: Util MFA（TOTP・メールOTP・Recovery）
  - 07: Repo 契約（PreReg/VerifyCode/WebAuthn/MFA/Session）
  - 08: レート制限・i18n ヘッダ（横断）
  - 09: Mail（テンプレート差し込み・i18n・署名・TTL・multipart）

## 記述形式
- 各ケースは **Given / When / Then** で要約し、**想定ステータス・本文の主要キー**を列挙。
- DTO 名・エンドポイントは仕様に合わせて表記（例: `/auth/pre-register`, `VerifyEmailResponse`）。

## テスト方法（Unit / UT）
### inmem プロファイルで UT（test フェーズのみ）
```shell
# /sansa-auth でビルドおよび実行
.\setcp.ps1
mvn -q -f sansa-auth/pom.xml -DskipTests clean package
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem test
```

### 特定クラス / メソッドのみ
```shell
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem -Dtest=AuthControllerValidationTest test
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem -Dtest=AuthControllerValidationTest#UT_01_001 test
```

### フォーク最適化（任意）
```shell
mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem -DforkCount=1C -DreuseForks=true test
```

### レポート出力場所
```shell
target/surefire-reports/
```
- メールテンプレート/パーサ（UT-09）は pytest-cov によるカバレッジ閾値を CI（ci-mail-offline.yml）で検証する。

### カバレッジ / レポート（JaCoCo）
- 本リポジトリは **既定ゴールが `verify`**。`verify` 実行で **毎回 HTML レポートとしきい値チェック**が走る。
- sansa-auth/pom.xml の defaultGoal=verify と JaCoCo（prepare-agent / prepare-agent-integration / report / check、coverage.min）を設定済み
- **ローカルの最低カバレッジ**は既定 **0%**（落とさない）。**CI は 100%** に上書きする。
  - ローカル例（0%）：  
    ```powershell
    mvn --% -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem verify
    ```
  - CI 例（100%）：  
    ```bash
    mvn -q -f sansa-auth/pom.xml -Dspring.profiles.active=inmem -Dcoverage.min=1.00 verify
    # もしくは ci-strict プロファイル（GitHub Actions では自動有効）
    ```
  - -Dcoverage.min=1.00 で失敗した場合は、除外設定（DTO/Config 等）や IT の未到達分岐を確認
- レポート出力先（UT/IT 集約）：  
  `sansa-auth/target/site/jacoco/index.html`

### Python（Mail パーサ用）テスト環境セットアップ

目的：UT-09（メールテンプレート／パーサ）のローカル検証用。  
CI 側では ci-mail-offline.yml で自動実行されます。

1. 仮想環境の作成・有効化  

    Windows（PowerShell）
    ```shell
    # リポジトリのルートで実行（requirements-dev.txt がある場所）
    python -m venv .venv
    .\.venv\Scripts\Activate.ps1

    # （初回のみ）スクリプト実行ポリシーで拒否された場合
    # Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
    # その後もう一度 .\.venv\Scripts\Activate.ps1
    ```

    macOS / Linux（bash / zsh）
    ```bash
    python3 -m venv .venv
    source .venv/bin/activate
    ```

2. 依存パッケージのインストール
    ```bash
    python -m pip install --upgrade pip
    pip install -r requirements-dev.txt
    ```

3. 実行（ローカル確認用：任意）
    ```bash
    # メールパーサUT（fixtures → expected_json の比較）
    pytest tests/unit_mailparse
    # カバレッジ表示（CI と同等の閾値チェック）
    pytest --cov=tests/unit_mailparse --cov-report=term-missing tests/unit_mailparse
    ```

4. 仮想環境の終了（任意）
    ```bash
    deactivate
    ```

補足
- requirements-dev.txt はリポジトリ直下を前提（CIも同一想定）
- 既に別 venv を使っている場合は .venv でなく既存の環境を流用しても可
- 失敗時は pytest -q -k UT-09 で対象を絞って原因切り分け
