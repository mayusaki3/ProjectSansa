# ProjectSansaドキュメント整理方針

本書は、ProjectSansa の既存ドキュメント群を HLDocS に対応させるための整理方針を定義する。

本書は、個別仕様の内容を変更するものではなく、ドキュメント体系・分類・移行順序・移行時の制約を定義する。

---

## 1. 目的

ProjectSansa のドキュメントを、HLDocS に基づく再現可能なドキュメント体系へ移行する。

移行では、以下を目的とする。

- README と docs 配下ドキュメントの役割を分離する
- 目次を HLDocS の index として再構成する
- 仕様・テスト仕様・利用手順・運用メモを document_type に基づいて分類する
- 既存ドキュメントの内容を保持したまま、階層・メタデータ・リンク構造を整理する
- spec から testspec、testspec から code へ追跡可能な構造を整備する

---

## 2. 適用範囲

本書は、以下の ProjectSansa ドキュメントに適用する。

- README.md
- docs/index.md
- docs/ja-JP/目次.md
- docs/ja-JP 配下の Markdown ドキュメント
- docs/ja-JP 配下に残る再構成中ドキュメント
- docs/ja-JP 配下に残る再構成前ドキュメント

Markdown 以外のファイルは、本書では直接の HLDocS 化対象としない。

ただし、Markdown ドキュメントから参照される補助ファイル、画像、テストスクリプト、設定例は、参照対象として整理対象に含める。

---

## 3. 基本方針

ProjectSansa のドキュメント整理では、以下を守る。

- HLDocS の共通ドキュメント構造に従う
- 先頭に LLM-MANAGED ブロックを配置する
- 先頭と末尾に同一の階層リンクを配置する
- 目次は document_type:index として扱う
- 仕様は document_type:spec として扱う
- テスト仕様は document_type:testspec として扱う
- 利用者向け手順は document_type:usage として扱う
- 作業記録・調査メモ・一時的な運用記録は document_type:note として扱う
- 既存本文の意味を変更しない
- 既存本文の削除・要約・省略を行わない
- 再構成前ドキュメントは、移行完了まで参照可能な状態を維持する

---

## 4. README.md の役割

README.md は、ProjectSansa の入口として扱う。

README.md には、以下のみを置く。

- ProjectSansa の概要
- 目的・構想の短い説明
- 開発者・参加者向けの導線
- docs/ja-JP/目次.md へのリンク
- リポジトリ利用上の最低限の案内

README.md には、以下を置かない。

- 詳細仕様
- API仕様
- テスト仕様
- 実装手順の詳細
- サーバー構築手順の詳細
- 長い設計判断
- 再構成中ドキュメントの一覧

README.md に既に存在する構想説明は、必要に応じて docs/ja-JP/仕様 配下の構想仕様へ移管する。

---

## 5. docs/ja-JP/目次.md の役割

`docs/ja-JP/目次.md` は、ProjectSansa 日本語ドキュメント全体の正規 index とする。

目次には、以下を置く。

- ドキュメント分類
- 各ドキュメントへの相対リンク
- 階層構造
- 最小限の分類ラベル

目次には、以下を置かない。

- 各ドキュメントの本文要約
- 仕様説明
- 判断基準
- 作業メモ
- TODO
- 再構成中・再構成前などの暫定見出し

再構成中・再構成前の分類は、移行作業中の管理情報であり、正規 index には残さない。

---

## 6. document_type 割当

ProjectSansa では、既存ドキュメントを以下の基準で document_type に割り当てる。

| 対象 | document_type | 備考 |
|---|---|---|
| 目次・一覧 | index | リンク列挙中心 |
| API仕様 | spec | エンドポイント単位またはサービス単位 |
| ドメイン仕様 | spec | リポジトリ、サービス、例外、モデル |
| データ定義 | spec | テーブル、スキーマ、列定義 |
| 共通仕様 | spec | 横断規約、共通設計、ポリシー |
| テストポリシー | spec または testspec | テストそのものの規約は spec、具体テストは testspec |
| テストケース・テストマトリクス | testspec | spec への Traceability を持つ |
| ユーザー向けマニュアル | usage | 操作手順・利用手順 |
| 運用向け Runbook | usage | 手順化された運用作業 |
| 監査・調査・作業メモ | note | 一時性または記録性が強いもの |
| 開発環境構築手順 | usage | 手順書として扱う |
| サーバー環境構築手順 | usage | 手順書として扱う |

判断に迷う場合は、本文の主目的で判定する。

仕様を定義している場合は spec、検証項目を定義している場合は testspec、手順を案内している場合は usage、記録・メモである場合は note とする。

## 8. 移行順序

ProjectSansa の HLDocS 移行は、以下の順で行う。

1. ドキュメント整理方針を作成する
2. `docs/ja-JP/目次.md` を HLDocS index として再作成する
3. README.md を入口文書として整理する
4. 共通仕様を HLDocS spec として整理する
5. API仕様を HLDocS spec として整理する
6. ドメイン仕様を HLDocS spec として整理する
7. データ定義を HLDocS spec として整理する
8. テスト仕様を HLDocS testspec として整理する
9. マニュアルを HLDocS usage として整理する
10. 運用メモを HLDocS note または usage として整理する
11. 再構成中・再構成前ドキュメントの分類を解消する

各段階では、対象ファイル群を明示し、移行前後のリンク切れを確認する。

---

## 9. 目次再構成方針

`docs/ja-JP/目次.md` の再構成では、以下を行う。

- LLM-MANAGED ブロックを追加する
- document_type を index に設定する
- canonical_title を `ProjectSansa 日本語ドキュメント目次` とする
- 既存リンクを現在の正規分類へ再配置する
- 再構成中・再構成前の暫定見出しを削除する
- リンク切れが疑われる項目は、移行保留一覧へ分離する
- 個別ドキュメントの要約は追加しない

目次の本文は、リンク列挙を主体とする。

---

## 10. Traceability 方針

ProjectSansa の仕様・テスト・コードの追跡関係は、以下の方向で整理する。

```text
spec
  ↓
testspec
  ↓
code
```

spec には、検証可能な仕様単位を配置する。

testspec には、対応する spec への参照を配置する。

code には、対応する spec または testspec を参照できる情報を配置する。

移行初期段階では、既存ドキュメントの内容維持を優先し、Traceability の完全付与は段階的に行う。

---

## 11. 既存ドキュメント移行時の禁止事項

既存ドキュメントの HLDocS 化では、以下を禁止する。

- 本文内容の削除
- 本文内容の要約
- 意味変更
- 仕様判断の推測追加
- 未確認ファイルへのリンク追加
- document_type の根拠なき変更
- 既存ファイル名の一括変更
- 既存ディレクトリの一括移動
- 再構成前ドキュメントの即時削除

内容修正が必要な場合は、HLDocS化とは別作業として扱う。

---

## 12. 移行保留一覧の扱い

以下に該当するドキュメントは、即時移行せず、移行保留一覧へ分離する。

- リンク先ファイルが確認できない
- 同名または類似名のファイルが複数存在する
- Markdown ではないが本文化が必要
- 内容が仕様・手順・メモの複数性質を持つ
- 現在の目次と実体パスが一致しない
- 旧版か正本か判断できない

移行保留一覧は、目次には正規ドキュメントとして混在させない。

---

## 13. 次工程

本書作成後、次に行う作業は `docs/ja-JP/目次.md` の HLDocS index 化である。

目次の HLDocS index 化では、以下を成果物とする。

- 差し替え後の `docs/ja-JP/目次.md`
- 移行保留一覧
- リンク切れまたは実体未確認項目の一覧
- 次に移行する対象ファイル群
