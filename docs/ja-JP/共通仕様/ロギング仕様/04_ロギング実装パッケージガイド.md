# ロギング実装パッケージガイド（com.sansa.logging）

## 1. 目的

本ドキュメントは、Project Sansa における **ロギング基盤の実装パッケージ構成および責務範囲** を定義する。

ロギング機能には以下が含まれる：

- システムログ（System Log）
- 監査ログ（Audit Log）
- 共通ログスキーマの構築・出力
- ロギング実装のテストおよび移行方針

本ドキュメントは **ドメイン非依存の実装方針** を対象とする。  
ドメイン固有のログイベント（例：AuthAuditEvent）については、各ドメインの適用ガイド（05_〜）で定義する。

---

## 2. パッケージ構成ポリシー

### 2.1 基本構成

```
com.sansa.logging
 ├─ SystemLogger            （システムログ用I/F）
 ├─ AuditLogger             （監査ログ用I/F）
 ├─ model/
 │    └─ AuditRecord        （監査ログ共通モデル）
 └─ impl/
      ├─ Slf4jSystemLogger  （SystemLogger実装）
      └─ JsonAuditLogger    （AuditLogger実装：JSON出力）
```

### 2.2 ドメインからの独立性

- **com.sansa.logging.* は、Auth / User / Session などのドメイン情報を保持しない。**
- ドメイン固有のログイベントは、sansa-auth 等のモジュール側が組み立てる。
- ロギング基盤は **「ログを受け取り、所定のフォーマットで出力する」** ことのみを責務とする。

---

## 3. ロギング基盤が提供するインターフェース

### 3.1 SystemLogger

```java
public interface SystemLogger {
    void info(String message, Object... args);
    void warn(String message, Object... args);
    void error(String message, Throwable ex, Object... args);
}
```

責務：

- 開発時・運用時の内部状態の把握
- 例外発生時の詳細ログ

---

### 3.2 AuditLogger

```java
public interface AuditLogger {
    void write(AuditRecord record);
}
```

責務：

- 認証・認可・操作ログなど「監査対象の行為」を記録
- 共通スキーマに従い JSON 形式で出力する

---

## 4. 共通モデル（AuditRecord）

### 4.1 目的

監査ログの共通項目を表現するためのモデル。  
ドメイン固有項目は保持しない。  
※ AuditRecord は監査ログの「ドメイン非依存な論理モデル」であり、
   実際の出力スキーマ（logId / environment / hash 等）は 
   AuditLogger 実装側で付与される。

### 4.2 フィールド例

```java
public class AuditRecord {
    private final String eventType;
    private final String userId;
    private final String result;       // "SUCCESS" / "FAILURE"
    private final String timestamp;
    private final Map<String, Object> details;
}
```

---

## 5. 実装方針

### 5.1 Slf4jSystemLogger

- SLF4J 経由で内部ログを出力  
- エラーログは Throwable を必ず含める  
- 本番運用では JSON ログにも拡張できるよう実装を疎結合に保つ  

---

### 5.2 JsonAuditLogger

- AuditRecord を JSON 化し、指定のログファイル・ログ基盤に出力  
- JSON は **監査ログスキーマ共通定義（03_ログスキーマ共通定義.md）** に従う  
- 出力例（整形前）

```json
{"eventType":"AUTH_LOGIN","userId":"12345","result":"SUCCESS", ...}
```

---

## 6. ドメイン適用時の責務分担

| 層 | 役割 |
|----|------|
| com.sansa.logging | ログ受取・シリアライズ・出力 |
| ドメイン（例：sansa-auth） | AuditRecord の組み立て（eventType, details など） |
| Controller / Service | 操作結果に応じて AuditLogger を呼び出す |

---

## 7. 移行方針（将来の sansa-logging モジュール化）

現時点では sansa-auth モジュール内で開発し、実装が安定した段階で以下を行う：

1. com.sansa.logging.* を物理的に新規モジュール `sansa-logging` に移動  
2. 各サービス（sansa-auth など）は sansa-logging へ依存するよう変更  
3. テストコードは sansa-logging に移動し、モジュール独立性を保証する  
4. ドメイン固有の実装（例：AuthAuditEvent）は各サービス側に残す  

---

## 8. テスト戦略

### 8.1 com.sansa.logging.* のテスト

- Slf4jSystemLogger 出力検証  
- JsonAuditLogger の JSON 生成と例外ハンドリング  
- AuditRecord のバリデーション（必須項目の存在確認）  
※ ログのローテーション・保持期間・削除については
   com.sansa.logging のテスト対象外とし、基盤側の責務とする。

### 8.2 ドメイン適用テスト（別ドキュメントで記述）

- eventType の決定ロジック（例：LOGIN_SUCCESS）  
- DomainException に応じた result / errorCode の確認  
- AuditLogger への呼び出しが正しく行われること  

詳細は **05_sansa-auth適用ガイド.md** で規定する。

---

## 9. 付録：ロギングパッケージの設計原則

1. **ドメイン非依存であること**  
2. **状態を持たないこと（stateless）**  
3. **JSON シリアライズ可能であること**  
4. **ログ出力方法（ファイル / 外部基盤）を切り替え可能であること**
