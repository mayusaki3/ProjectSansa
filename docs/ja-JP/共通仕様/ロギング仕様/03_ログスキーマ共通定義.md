# ログスキーマ共通定義（Project Sansa 共通）

## 1. 目的

Project Sansa 全体で共通利用する  
**監査ログ（audit）およびシステムログ（system）** のスキーマを定義する。

スキーマは、  
- JSON 形式での表現  
- ストレージ（Cassandra / Elasticsearch / File / Cloud Logging 等）へのマッピング  
の両方を想定した、最小限で汎用的な仕様とする。

---

## 2. 全ログ共通フィールド

以下は監査ログ・システムログで共通に使用するフィールド定義。

| フィールド | 型 | 必須 | 説明 |
|-----------|----|------|------|
| logId | string(UUID) | 必須 | ログレコード固有の UUID |
| timestamp | string(ISO-8601) | 必須 | ログ発生時刻（UTC） |
| service | string | 必須 | ログを出力したサービス名（例：sansa-auth, sansa-web） |
| environment | string | 必須 | 実行環境（dev/stg/prod 等） |
| level | string | 必須 | INFO / WARN / ERROR など（監査ログの場合は利用しない / 固定） |

※ **監査ログは level を内部的に INFO 相当で固定し、外部公開しない。**  
※ **システムログは level を利用して通常のログレベル管理を行う。**

---

## 3. 監査ログ専用フィールド

### 3.1 フィールド一覧

| フィールド | 型 | 必須 | 説明 |
|-----------|----|------|------|
| eventType | string | 必須 | ログイベント識別子（LOGIN_SUCCESS など） |
| actorUserId | string | 任意 | 操作主体のユーザーID（未認証時は null） |
| actorSessionId | string | 任意 | 操作主体のセッションID（あれば） |
| targetUserId | string | 任意 | 操作対象となるユーザー |
| targetResourceId | string | 任意 | 操作対象リソース（キー・ID 等） |
| result | string | 必須 | SUCCESS / FAILURE |
| errorCode | string | 任意 | DomainException の code（失敗時のみ） |
| failureReason | string | 任意 | 仕様で定義された簡易ラベル（多言語依存なし） |

---

## 4. システムログ専用フィールド

| フィールド | 型 | 必須 | 説明 |
|-----------|----|------|------|
| message | string | 必須 | 開発・運用向けのログメッセージ |
| detail | object | 任意 | 追加情報（構造化 JSON 推奨） |
| stackTrace | string | 任意 | 例外発生時のみ記録（監査ログには持ち込まない） |
| cause | string | 任意 | 原因例外のクラス名など |

---

## 5. ネットワーク情報のフィールド定義（監査共通）

### 5.1 記録内容

| フィールド | 型 | 必須 | 説明 |
|-----------|----|------|------|
| clientIpHash | string | 任意 | クライアント IP のハッシュ値 |
| userAgentHash | string | 任意 | User-Agent のハッシュ値 |

### 5.2 記録禁止事項

- 平文 IP
- 生の User-Agent 全文
- Cookie 値
- Authorization ヘッダ
- トークン文字列

---

## 6. 改ざん検出のためのフィールド（監査ログのみ）

| フィールド | 型 | 必須 | 説明 |
|-----------|----|------|------|
| previousHash | string | 本番:必須 / 開発:任意 | 直前レコードのハッシュ値（チェーン構造） |
| recordHash | string | 本番:必須 / 開発:任意 | 本レコードのダイジェスト |
| signature | string | 本番:必須 / 開発:任意 | HMAC / 署名値 |
| keyId | string | 本番:必須 / 開発:任意 | 使用した署名キー ID（kid） |

※ フィールド自体はスキーマ上は「省略可」だが、本番環境の監査ログでは [ロギングポリシー > ログのライフサイクル管理 (8.3 監査ログのライフサイクル > 改ざん耐性)](./01_ロギングポリシー.md#8-ログのライフサイクル管理共通) に従い、recordHash / previousHash / signature / keyId を必須とする。 開発・CI では任意（原則生成）とする。

---

## 9. スキーマ管理方法（推奨）

- 本ファイルを「正」とし、Sansa 各サービスはこれを読み込む形で生成的に対応する（推奨）
- Logstash・Fluent Bit・Cassandra マッピングは別途定義
- TypeScript/Java DTO はこの仕様から生成可能な構造をとる
- 監査ログの保存期間・廃棄方針は [ロギングポリシー > ログのライフサイクル管理](./01_ロギングポリシー.md#8-ログのライフサイクル管理共通) を正とする。
