# テスト番号と出力フォーマット

## 1. テスト番号設計の基本方針

テスト番号は以下を満たすことを目的とする。

- ログを見ただけで「**何のテストか**」が分かる
- プロジェクト横断で **衝突しない**
- 仕様書・マトリクス・コードを **機械的に突合可能**

---

## 2. テスト番号体系（共通）

### 2.1 共通基盤（testkit / logging）

形式：

- `TESTKIT-<FUNC>-TC-XXX`
- `LOGGING-COMMON-TC-XXX`

例：

- `TESTKIT-TP-TC-001`
- `LOGGING-COMMON-TC-101`

用途：

- 共通基盤として **業務モジュール非依存**
- UT / IT の区別よりも **機能単位の検証**を重視

---

### 2.2 業務モジュール（推奨）

形式：

- `<MODULE>-COMMON-UT-XXX`
- `<MODULE>-COMMON-IT-XXX`

例（sansa-auth）：

- `AUTH-COMMON-UT-001`
- `AUTH-COMMON-IT-003`

---

### 2.3 プロジェクト横断テスト（将来）

形式例：

- `CROSSTEST-AUTH-LOGGING-IT-001`

用途：

- 複数モジュールをまたぐ結合・E2E 検証

---

## 3. TestPrinter 出力フォーマット

### 3.1 ケース単位

- 成功：`✅ AUTH-COMMON-UT-001`
- 失敗：`❌ AUTH-COMMON-UT-002`

### 3.2 サマリ

- `--- SUMMARY AUTH-COMMON-UT: OK=3 / NG=0 / TOTAL=3 ---`

---

## 4. TestPrinter 非使用時

testkitモジュールのみ、以下の簡易形式を許容する。

- `[TESTCASE] TESTKIT-TP-TC-001`

---

## 5. ダミー実装の表現

- `@DummyImplementation` が付与されたクラスを対象とするテストは  
  出力ログに `[DUMMY]` を付与する

例：

```text
✅ AUTH-COMMON-UT-005 [DUMMY]
```
